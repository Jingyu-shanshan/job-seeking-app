# 简历和求职信的书写语言

状态：用户于 2026-10-29 要求按计划实施；功能已实现，验收记录见对应计划。

## 用户需求

生成简历和 cover letter 时可以选择中文或芬兰语，同时保留默认英语。

## 建议的最小范围

- 在职位页的简历、求职信两行分别提供语言选择：English、中文、Suomi；值为 `en`、`zh`、`fi`，中文采用简体。
- 没有草稿时默认英语；有草稿时默认该类最新草稿的语言。每次生成明确发送选择值。
- 语言属于生成结果：存入草稿，审阅页显示，文档正文、章节标题、称呼和落款使用该语言。应用导航和操作提示仍沿用现有英文。
- 更换语言会生成新草稿，不会翻译或覆盖旧草稿、手工修改或已有 PDF。最新草稿仍按每个职位文本、每种文档各一份展示。
- 最新草稿语言不同，允许使用相同事实重新生成；语言和事实均相同则维持现有拒绝重复生成规则。由英语切换中文再切回英语，属于新生成，会收费，不复用历史草稿。
- 旧 API 请求省略语言时按英语处理；既有草稿迁移为英语；旧英文文档的正文、文件名和 PDF 有效性保持一致。
- 非英语文件名附加语言代码用于区分；英语文件名保留现有格式。
- 人名、公司名、产品名、技术名词、联系方式保持原样；日期使用 `YYYY-MM`，数量使用阿拉伯数字。引用事实版本、原始 JD 引文保持原文。
- 支持英语、中文、芬兰语事实中的常用数量限定词和状态表达；不得以选择非英语为由跳过校验。无法识别的翻译不自动证明正确，继续保守排除并展示原因。
- PDF 沿用浏览器打印和上传文本核对流程；中芬字符必须可显示、可提取，不能将扫描 PDF 视为通过。

以上交互、简体中文、历史草稿策略和文件名策略是本次规划建议，并非用户逐项指定。

## 方案比较

1. **每次生成选择语言（建议）**：沿用已有生成按钮、不可变草稿和 PDF 流程；两类文档可独立选择，无需新增个人设置或语言版本管理。
2. **个人资料设置全局语言**：入口较少，但不同职位或两种文档需要不同语言时不便，还需处理全局偏好。
3. **导出时翻译**：不能直接复用已审阅语句和证据，需要再次生成、审阅及计费，不适合本需求。

## 约束

- 不新增依赖，不新增模型调用步骤；每次点击仍只发送一次 DeepSeek 请求。
- 不增加发送给模型的个人资料；沿用事实确认和可见性限制，保留费用记录、失败记录和并发保护。
- 不修改原始事实、JD 引文、历史草稿正文或已保存的 PDF。
- 不放宽无引用、撤销事实、数字、限定词、状态、敏感信息、占位符或 PDF 文本校验。
- 不做全站国际化、语言自动识别、任意语言输入、历史语言版本列表或自动翻译已编辑文本。
- 测试仅使用虚构数据；真实模型调用需要另行明确数据和费用上限。

## 验收重点

1. 默认英语与现有行为兼容，中文和芬兰语分别作用于两种文档。
2. 语言经过请求校验、并发保护、模型提示、持久化、读取和文档呈现完整传递。
3. `about 30%` → `约30%` / `noin 30 %` 不被误拒绝，变成 40% 或丢失限定词仍被拒绝。
4. `basic (A2)` → `基础（A2）` / `perustaso (A2)` 保留状态；省略基础限制或把预计毕业写成已毕业仍被拒绝。
5. 旧草稿/PDF 可继续读取；新语言 PDF 的遗漏、额外文字或越界仍会失败。

## 校验边界

现有检查是规则检查，并非语义证明。增加有限、明确的三语表达映射和回归样例，不开发通用翻译验证器；无法确认的表达继续让用户审阅。芬兰语准确性和实际中文打印需在实现后人工抽查，不用模拟模型响应声称真实生成质量已验证。
