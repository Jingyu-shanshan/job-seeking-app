# 开发 Tasks

状态：规划中。`[x]` 表示本轮完成的仓库准备；其余均**未开发**。任务以 [原始方案](PRODUCT_PLAN.md) 的 V0.1→V0.2 顺序排列，验收时使用真实、获准使用的资料。

## P0：项目准备

- [x] **T00 本地项目与决策**：初始化 Git、保存原方案、确定 V0.1 技术栈、项目目录、复用候选与任务。验收：仓库可读，源方案和本轮决策能区分。
- [ ] **T01 可运行骨架**：在 `apps/web` 建 Angular 22 页面，在 `apps/server` 建 Node 24/Fastify 5 本地服务；配置 npm 工作区与锁文件，限定 loopback，形成一次前后端健康请求。验收：新机器按 README 可启动，浏览器不能从非授权 Origin 调用写接口。
- [ ] **T02 数据最小模型**：只实现事实、JD 快照、匹配、材料、申请及版本关系；Markdown 与 SQLite 各有明确主数据，做迁移、原子写入及基本备份路径。验收：重启后数据仍在，已确认事实正文被修改后需重新确认，历史快照不变。

## V0.1：一份 JD 到人工申请

- [ ] **T03 个人事实**：录入经历、技能与公开表述，支持 proposed/confirmed 状态及来源、版本；履历文件导入按真实需要后加。验收：未确认或禁止外发的内容不能用于正式生成。
- [ ] **T04 手动 JD**：粘贴 JD 并保存来源、原文、获取时间与内容哈希；允许用户更正解析。验收：不改写原文，未知语言/地点等字段保持未知。
- [ ] **T05 硬条件与证据匹配**：确定性筛选优先，输出“符合/不符合/待确认”的原因及 JD 要求→事实 ID 映射；语义解释只在需要时调用模型。验收：未知不算通过，模型不能把硬条件失败改成合格。
- [ ] **T06 材料草稿与事实校验**：从已确认且可公开的事实生成一份简历和求职信；个人陈述绑定事实，数字、日期、技能和敏感内容校验。验收：凭空新增的经历或数字被标记并阻止审核通过。
- [ ] **T07 人工审核与 PDF**：展示每条陈述的事实依据、修订差异和待确认项；固定模板导出可复制文字的 PDF。验收：用户修改后重新校验；PDF 无缺字、截断，名称/日期/数字一致。
- [ ] **T08 申请版本**：保存 JD、事实、匹配和材料快照；用户可导入实际投递文件并手动确认申请时间。验收：仅导出或打开链接不改变“已申请”，后来改事实不改写历史申请。
- [ ] **T09 完整备份/恢复**：包括 Vault、SQLite、不可再生原始文件和实际投递文件，校验清单与恢复结果。验收：从备份在空数据目录恢复后，事实、状态和文件版本一致。
- [ ] **T10 真实流程验证**：用少量真实 JD 覆盖明确匹配、明显不匹配、关键未知和无证据陈述；记录人工审核耗时、问题与费用。验收：至少完成一套本人愿意实际投出的材料，且来源和事实可追溯。

## V0.2：验证 V0.1 后再做

- [ ] **T11 定向发现**：公司关注名单加**一种**公开 ATS API（按真实目标公司选 Greenhouse/Lever/Ashby）；用原生 `fetch`，做来源限流、去重与新鲜度。验收：不足目标时报告实际数量和原因，不扩大来源或偷偷放宽条件。
- [ ] **T12 运行配置与预算**：保存预设和本次快照，区分发现、短名单、材料、申请计划的数量；限制请求、时间和估算费用，支持停止/恢复。验收：重试不重置预算或重复创建申请，后台不发送申请。
