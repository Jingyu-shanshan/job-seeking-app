- [ ] **T01 单服务骨架与工程约定**：npm 工作区内生成 Angular 22、Node 24/Fastify 5 和 `packages/shared`（Web 与 API 共用的 schema/类型：Fastify 用它校验入参，Angular 用它生成类型）；服务端的规则（硬条件评估、陈述校验、状态流转）放在不依赖 Fastify/`pg` 的纯模块，便于脱离数据库测试。生产构建由 Fastify 同源提供页面和 `/api`，读取 Railway `PORT` 并监听 `0.0.0.0`，本地默认 loopback。同时决定测试运行器、lint/格式化和 CI，并把真实命令（含运行单个测试的方式）写入 `CLAUDE.md`。验收：一个进程能返回首页与 `/health`，直接刷新 Angular 深层路由仍可打开；`npm test` 与 `npm run lint` 在本地和 CI 通过；无真实凭据入仓库。
- [ ] **T02 PostgreSQL 与迁移**：用 `pg` 接 PostgreSQL，以 `node-pg-migrate` 管理版本化迁移；定义事实、JD、匹配、材料、申请的最小表。事实用不可变版本：`fact` + 只追加的 `fact_version`（正文、哈希、来源、状态、可见性），材料中的陈述和冻结的申请以外键引用版本 ID，不复制正文。提供数据库 `/health/ready`。验收：空库可独立迁移，重复执行无副作用，重启保留数据；连接失败返回非 2xx，Neon 休眠唤醒/idle 断线不会使进程崩溃；数据层集成测试连真实 PostgreSQL（本地容器或独立 Neon 分支）；对样例数据做一次最小的备份→隔离库恢复演练（完整版在 T10）。
- [ ] **T03 单用户认证**：Better Auth 接 PostgreSQL，生成认证表 SQL 并纳入同一版本化迁移；生产关闭公开注册，提供受控的首次账户创建流程，所有私有 API 做服务端会话检查。验收：空库执行**全部业务及认证迁移**后可以首次登录；未登录不能读写资料，跨来源写请求被拒绝。
- [ ] **T03a 骨架预部署（一次性，无个人数据）**：在一次性的 Neon 项目和 Railway 服务上部署 T01–T03 的骨架（登录页 + `/health/ready`），走真实的 pre-deploy 迁移和 Fastify 同源托管，并在创建时选定区域（见 [部署文档](DEPLOYMENT.md)）。需要用户先决定远程仓库或 Railway CLI 发布方式并自行创建账户。验收：HTTPS 登录可用、未登录被拒；迁移失败会中止发布；最终 JS bundle 不含任何服务端变量；不含个人事实或真实 JD，验证后可销毁。这只是 T12 的演练，不代表正式发布。

## V0.1：一份 JD 到人工申请

- [ ] **T04 个人事实**：录入经历、技能及公开表述，以 T02 的不可变版本保存来源、正文哈希、状态（proposed/confirmed）；确认绑定到版本，编辑产生新的 proposed 版本。可见性为两个独立开关：“可发送给模型供应商”与“可出现在正式材料”。Markdown 导入只生成待确认项。验收：未确认或禁止外发的内容不能用于正式材料，也不会进入模型请求；正文变更需重新确认。
- [ ] **T05 手动 JD**：粘贴 JD，保存来源、原文、时间与版本；抽取出的每条要求保存 JD 原文引用片段（做子串校验，校验不过的标为待确认），允许用户更正解析。验收：不改写原始快照，缺失的语言/地点等字段保持未知。
- [ ] **T06 硬条件与证据匹配**：基于 T05 带原文片段的要求，规则先筛选，再按需要调用模型解释；输出“符合/不符合/待确认”的原因及 JD 要求→事实版本 ID 映射，界面可跳转到 JD 原文片段。验收：未知不算已满足，模型不能推翻硬条件失败。
- [ ] **T07 材料草稿与事实校验**：“选择再渲染”——模型只返回结构化输出，每条陈述引用已确认且可公开的事实版本 ID；确定性校验器核对数字、日期、技能与所引事实一致并检查敏感信息，无引用的自由文本不能进入材料。验收：新增未证实经历或无引用陈述被标记/拒绝，不能通过最终审核。
- [ ] **T08 人工审核与 PDF**：展示逐条证据与修改差异，固定 HTML/CSS 模板先验证浏览器 PDF。验收：编辑后重验；PDF 可提取文字，无缺字、截断，名称/日期/数字一致。
- [ ] **T09 申请版本**：冻结当时 JD、事实版本、匹配和材料（引用版本 ID）；实际投递 PDF/文件有大小上限、哈希和版本，由用户确认申请时间。验收：只导出或打开链接不计“已申请”，修改现有事实不改变历史投递。
- [ ] **T10 导出与恢复**：导出 Markdown/JSON/PDF；使用 PostgreSQL 备份在隔离库恢复事实、状态、快照与附件；另配置定期 `pg_dump` 到用户控制、且与 Neon 不同提供方的存储，并核对所选 Neon 套餐的时间点恢复窗口。验收：恢复后的申请状态和实际投递文件与原版一致，不依赖 Railway 容器目录；至少成功恢复一份独立于 Neon 的备份。
- [ ] **T11 真实流程验证**：用少量获准使用的 JD 覆盖匹配、不匹配、关键未知和无证据陈述，记录审核时间与费用。验收：至少完成一套本人愿意实际投出的材料，来源与事实可追溯。
