## P0：可运行且可保护数据的骨架

- [x] **T00 项目决策**：本地 Git、原方案、最小目录和开源调研已建立；2026-09-29 更新 Railway + Neon 目标。验收：原方案与当前实施决策分开保存。
- [ ] **T01 单服务骨架**：npm 工作区内生成 Angular 22 与 Node 24/Fastify 5；生产构建由 Fastify 同源提供页面和 `/api`，读取 Railway `PORT` 并监听 `0.0.0.0`，本地默认 loopback。验收：一个进程能返回首页与 `/health`，直接刷新 Angular 深层路由仍可打开；无真实凭据入仓库。
- [ ] **T02 PostgreSQL 与迁移**：用 `pg` 接 PostgreSQL，以 `node-pg-migrate` 管理版本化迁移；定义事实、JD、匹配、材料、申请的最小表与版本关系，并提供数据库 `/health/ready`。验收：空库可独立迁移，重复执行无副作用，重启保留数据；连接失败返回非 2xx，Neon 休眠唤醒/idle 断线不会使进程崩溃。
- [ ] **T03 单用户认证**：Better Auth 接 PostgreSQL，生成认证表 SQL 并纳入同一版本化迁移；生产关闭公开注册，提供受控的首次账户创建流程，所有私有 API 做服务端会话检查。验收：空库执行**全部业务及认证迁移**后可以首次登录；未登录不能读写资料，跨来源写请求被拒绝。

## V0.1：一份 JD 到人工申请

- [ ] **T04 个人事实**：录入经历、技能及公开表述，保存来源、正文哈希、版本与 proposed/confirmed；Markdown 导入只生成待确认项。验收：未确认或禁止外发的内容不能用于正式材料，正文变更需重新确认。
- [ ] **T05 手动 JD**：粘贴 JD，保存来源、原文、时间与版本；允许用户更正解析。验收：不改写原始快照，缺失的语言/地点等字段保持未知。
- [ ] **T06 硬条件与证据匹配**：规则先筛选，再按需要调用模型解释；输出“符合/不符合/待确认”的原因及 JD 要求→事实 ID 映射。验收：未知不算已满足，模型不能推翻硬条件失败。
- [ ] **T07 材料草稿与事实校验**：只选已确认且可公开事实生成一份简历和求职信；检查无依据数字、日期、技能与敏感信息。验收：新增未证实经历被标记，不能通过最终审核。
- [ ] **T08 人工审核与 PDF**：展示逐条证据与修改差异，固定 HTML/CSS 模板先验证浏览器 PDF。验收：编辑后重验；PDF 可提取文字，无缺字、截断，名称/日期/数字一致。
- [ ] **T09 申请版本**：冻结当时 JD、事实、匹配和材料；实际投递 PDF/文件有大小上限、哈希和版本，由用户确认申请时间。验收：只导出或打开链接不计“已申请”，修改现有事实不改变历史投递。
- [ ] **T10 导出与恢复**：导出 Markdown/JSON/PDF；使用 PostgreSQL 备份在隔离库恢复事实、状态、快照与附件。验收：恢复后的申请状态和实际投递文件与原版一致，不依赖 Railway 容器目录。
- [ ] **T11 真实流程验证**：用少量获准使用的 JD 覆盖匹配、不匹配、关键未知和无证据陈述，记录审核时间与费用。验收：至少完成一套本人愿意实际投出的材料，来源与事实可追溯。
